# 公开数据脱敏规范

本规范适用于仓库内 `api/holyland/`、`api/lineups/`、`api/items.json` 和 `api/catalogs.json`。公开数据使用严格字段白名单：导出时只重新构造允许公开的对象，不直接复制采集或解析结果。

## 圣域赛果

圣域赛果只保留页面展示所需的信息：赛季、渠道、圣域分区、记录时间、赛程名称、比赛结果，以及参赛者的区服编号、公开昵称、头像编号和头像框编号。

公开昵称和区服是圣域对阵页面原有的公开赛果信息，因此继续保留。不得加入账号 ID、角色内部 ID、设备信息、联系方式或其他可用于关联私有账户的数据。

有可用阵容的比赛只保存随机生成的 16 位十六进制 `lineup_id`。该值不是原始回放 ID 的截取或哈希，不能反推出原始标识。每次完整导出可以重新生成，外部不得依赖它作为长期稳定标识。

## 圣域阵容

每份阵容文件只允许以下信息：

- 顶层：结束回合、最大回合、记录时间、双方阵容。
- 参赛方：区服编号、公开昵称、上阵英雄、助战英雄、魔宠。
- 英雄或魔宠：展示名称、等级、星级、站位、公开素材标识、品质、星痕或月痕展示信息、阵营和强度。

以下信息禁止公开：

- 原始回放 ID、文件名或可反查原始回放的映射。
- `player_id`、`record_id`、`base_id` 等内部标识。
- 血量、战斗分组、内部展示结构、地图或战斗实例信息。
- 抓取目录、Windows 绝对路径、源文件位置和采集工具状态。
- Cookie、令牌、密码、密钥或其他认证数据。

## 指尖百科

百科只保留静态展示所需的名称、说明、分类、品质、素材标识、星级、阵营、强度、碎片标记和礼包内容。礼包内容只引用公开物品编号及数量。

不得加入资源源路径、资源包位置、解析记录、调试字段或采集环境信息。

### 分类图鉴

`api/catalogs.json` 包含资料版本日期，以及角色、符文、魔宠、圣物、兽印五个静态列表。物品图鉴继续使用 `api/items.json`。

新图鉴的公开字段仅允许：

- 条目：公开物品编号、名称、说明、现有图片素材标识与展示种类、品质、展示星级、阵营／定位／评级的中文标签、类型、展示标签、技能、成长说明和备注。
- 技能：名称、展示类型、纯文字效果说明。
- 成长说明：展示阶段名称、纯文字效果说明。

兽印技能允许增加 `pets`，仅为适用魔宠的公开中文名称列表；不保留原适用效果编号。角色允许增加 `star_traces`，仅包含阶段名称与纯文字新增效果，完整覆盖有对应资料的 18 名角色各 15 阶。

角色 `growth` 只允许初始四属性数值及公开等级／星级上限。圣物 `growth` 只允许等级上限、星级、四属性数值和全属性加成百分数，不保留原始角色、圣物、被动或关联编号。

新增 `api/growth.json` 使用独立展示结构：资料日期、四属性中文名称、职业中文名称、圣物品质、连续等级、公开材料编号与数量、四属性数值、进阶阶段及等级上限、公开星级档位及等级上限。数值表共收录四职业各 1,500 级及三种圣物品质各 2,000 级。不得公开原始字段名、成本表达式、客户端枚举、服务端协议或原数据映射。

条目编号使用公开物品编号；不得发布原始角色、魔宠、圣物或技能的内部编号。关联配置时只在临时工作目录内使用这些编号，导出结果不得保留任何映射。原始富文本先转换为纯文字，网页再转义展示，不把客户端标签或脚本写入详情。

明确标记隐藏／未使用的条目不进入新图鉴。角色范围对应现有公开物品中的角色本体。两件新增圣物没有已有图标时保留空素材标识，页面显示占位，不引用远程资源或资源包路径。

仓库不保存原始配置表、客户端模块、协议、反编译代码、来源清单、提取／解包工具或请求游戏服务器的采集脚本。所有图鉴请求只读取同一站点内的静态 JSON 和现有图片，与游戏账户、游戏接口无关。

## 发布检查

`tests/public-data.test.cjs` 会在 `npm test` 中执行，并检查：

- 所有 JSON 对象只能出现对应白名单字段。
- 阵容文件名和赛果引用必须是 16 位随机十六进制编号。
- 每个阵容引用必须恰好对应一个文件，且不得遗留无引用阵容。
- 数据中不得出现内部标识、本地绝对路径或回放文件名。
- 图鉴嵌套对象执行严格白名单检查，文本不包含客户端富文本或资源路径。
- 图片标识对应已存在的公开素材；图鉴中的公开编号唯一，技能与成长说明结构完整。
- 新增生产文件不得包含客户端模块、原始配置、游戏接口请求或采集工具。

发布前还应运行 `npm run test:browser`，确认圣域赛果、阵容展开、百科分类和既有页面功能均可在静态 HTTP 服务下正常工作。任何白名单变更都必须先更新本规范和自动化测试，再重新审查将要公开的数据。
