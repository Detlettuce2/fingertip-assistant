# 公开数据脱敏规范

本规范适用于仓库内 `api/holyland/`、`api/lineups/` 和 `api/items.json`。公开数据使用严格字段白名单：导出时只重新构造允许公开的对象，不直接复制采集或解析结果。

## 圣域赛果

圣域赛果只保留页面展示所需的信息：赛季、渠道、圣域分区、记录时间、赛程名称、比赛结果，以及参赛者的区服编号、公开昵称、头像编号和头像框编号。

公开昵称和区服是圣域对阵页面原有的公开赛果信息，因此继续保留。不得加入账号 ID、角色内部 ID、设备信息、联系方式或其他可用于关联私有账户的数据。

有可用阵容的比赛只保存随机生成的 16 位十六进制 `lineup_id`。该值不是原始回放 ID 的截取或哈希，不能反推出原始标识。每次完整导出可以重新生成，外部不得依赖它作为长期稳定标识。

## 圣域阵容

每份阵容文件只允许以下信息：

- 顶层：结束回合、最大回合、记录时间、双方阵容。
- 参赛方：区服编号、公开昵称、上阵英雄、助战英雄、魔宠。
- 英雄或魔宠：展示名称、等级、星级、站位、公开素材标识、品质、星痕或月痕展示信息、阵营和强度。

以下信息禁止公开：

- 原始回放 ID、文件名或可反查原始回放的映射。
- `player_id`、`record_id`、`base_id` 等内部标识。
- 血量、战斗分组、内部展示结构、地图或战斗实例信息。
- 抓取目录、Windows 绝对路径、源文件位置和采集工具状态。
- Cookie、令牌、密码、密钥或其他认证数据。

## 指尖百科

百科只保留静态展示所需的名称、说明、分类、品质、素材标识、星级、阵营、强度、碎片标记和礼包内容。礼包内容只引用公开物品编号及数量。

不得加入资源源路径、资源包位置、解析记录、调试字段或采集环境信息。

## 发布检查

`tests/public-data.test.cjs` 会在 `npm test` 中执行，并检查：

- 所有 JSON 对象只能出现对应白名单字段。
- 阵容文件名和赛果引用必须是 16 位随机十六进制编号。
- 每个阵容引用必须恰好对应一个文件，且不得遗留无引用阵容。
- 数据中不得出现内部标识、本地绝对路径或回放文件名。

发布前还应运行 `npm run test:browser`，确认圣域赛果、阵容展开、百科分类和既有页面功能均可在静态 HTTP 服务下正常工作。任何白名单变更都必须先更新本规范和自动化测试，再重新审查将要公开的数据。
